Documentación de Ribbon UI Studio

Del archivo de Office a una cinta RibbonX completa, sin separar XML, VBA e iconos.

Ribbon UI Studio reúne edición de customUI XML, callbacks VBA, vista previa de Excel, Word y PowerPoint, iconos imageMso, imágenes personalizadas, creación de complementos y empaquetado para Windows en un solo flujo.

Introducción

Un editor centrado en el proyecto completo de RibbonX.

Ribbon UI Studio trabaja directamente con la estructura interna de los archivos Open XML de Microsoft Office. Puede localizar o crear la parte customUI, abrirla en Monaco, escribir los cambios nuevamente en el paquete Office y mantener juntos los recursos relacionados con la cinta.

Para editar

Abre un documento existente, revisa su árbol interno, edita RibbonX, valida, formatea, gestiona imágenes y trabaja con los módulos VBA relacionados.

Para crear

Genera complementos base para Excel, Word o PowerPoint con Ribbon y módulo de callbacks, y continúa desarrollándolos desde el mismo editor.

Idea central: el XML del Ribbon y el código VBA no se tratan como texto aislado. Se mantienen asociados al archivo Office que realmente los contiene.
Antes de empezar

Requisitos del entorno.

ComponenteCuándo se necesita
Windows 10 / 11Plataforma de escritorio de Ribbon UI Studio.
Microsoft Office de escritorioNecesario para crear o modificar proyectos VBA y generar complementos nativos de Excel, Word y PowerPoint.
Archivo habilitado para macrosNecesario si el proyecto usará callbacks VBA. Por ejemplo .xlsm, .docm, .pptm o formatos de add-in.
Inno Setup 6Necesario únicamente cuando se desea generar el instalador Windows del complemento desde la ruta de empaquetado actual.
Copia de seguridad: antes de modificar un archivo importante, conserva una copia. Ribbon UI Studio escribe dentro del paquete Office y puede modificar también su proyecto VBA.
Inicio rápido

Tu primera edición en cuatro pasos.

1Abre el archivoSelecciona un documento o complemento compatible.
2Abre o crea RibbonXUsa Office 2007 o Office 2010+ según el proyecto.
3Edita y validaTrabaja en Monaco, genera controles y revisa diagnósticos.
4Guarda y pruebaEscribe el paquete Office y vuelve a abrirlo en Office.

Al abrir un documento, el panel de archivos muestra su contenido interno. Si ya existe una parte RibbonX puedes abrirla; si no existe, puedes crear una estructura válida y registrarla dentro del paquete.

Compatibilidad

Formatos Open XML y complementos que puede abrir.

Word

.docx.docm.dotx.dotm

Excel

.xlsx.xlsm.xltx.xltm.xlam

PowerPoint

.pptx.pptm.potx.potm.ppsx.ppsm.ppam

Importante: un archivo sin macros, como .xlsx, .docx o .pptx, sí puede contener RibbonX, pero no puede almacenar el código VBA necesario para callbacks. Si necesitas callbacks, guarda primero el documento en un formato habilitado para macros.
Interfaz

Árbol del archivo + pestañas Monaco + Ribbon de herramientas.

El espacio principal combina el árbol interno del archivo Office con el editor Monaco. El XML y los módulos VBA se abren como documentos independientes, por lo que cambiar de un callback al Ribbon no implica reemplazar el contenido de la pestaña activa.

Árbol del documento

Permite localizar la parte RibbonX, imágenes embebidas y módulos disponibles, manteniendo el contexto del archivo que se está editando.

Pestañas del editor

XML y VBA usan su propio lenguaje, nombre y origen. Los cambios pendientes se controlan por documento antes de guardar o empaquetar.

Espacio principal de edición: árbol del paquete Office, Ribbon de herramientas y editor Monaco.
RibbonX

Office 2007 y Office 2010+ usan partes diferentes.

Ribbon UI Studio reconoce los dos namespaces principales de RibbonX y utiliza la ruta correcta dentro del paquete Office.

EsquemaNamespaceRuta habitual
Office 2007http://schemas.microsoft.com/office/2006/01/customuicustomUI/customUI.xml
Office 2010+http://schemas.microsoft.com/office/2009/07/customuicustomUI/customUI14.xml
RibbonX mínimo — Office 2010+
<?xml version="1.0" encoding="UTF-8"?>
<customUI xmlns="http://schemas.microsoft.com/office/2009/07/customui" onLoad="RibbonLoad">
  <ribbon>
    <tabs>
      <tab id="tabDemo" label="Mi complemento">
        <group id="grpDemo" label="Herramientas">
          <button id="btnDemo"
                  label="Ejecutar"
                  imageMso="HappyFace"
                  size="large"
                  onAction="MyAction" />
        </group>
      </tab>
    </tabs>
  </ribbon>
</customUI>
Cuando creas una parte RibbonX nueva, Ribbon UI Studio no se limita a escribir el XML: también registra la relación y el tipo de contenido necesarios dentro del archivo Office.
Productividad

Empieza con estructuras completas, no con etiquetas sueltas.

El Ribbon de herramientas puede insertar ejemplos de Office 2007 y 2010+, además de controles y estructuras frecuentes. El proyecto incluye plantillas para botones, grupos, menús dinámicos, galerías y escenarios de ejemplo.

Controles y grupos

Inserta estructuras RibbonX válidas como punto de partida y adapta id, label, tamaño, imagen y callbacks.

Revisión

Valida primero; abre Office después.

El analizador puede comprobar que el XML sea sintácticamente válido, formatearlo y detectar la versión del namespace. El diagnóstico de Ribbon combina el XML con el código VBA disponible y los iconos embebidos para encontrar problemas antes de probar el documento en Office.

XML

Valida estructura, namespace y contenido; extrae IDs, imageMso e imágenes personalizadas y puede generar un reporte legible de Tab → Group → Control.

Callbacks

Compara los callbacks declarados en RibbonX con el VBA disponible para detectar firmas faltantes o inconsistentes.

Un XML bien formado no garantiza por sí solo que el Ribbon funcione. Un onAction inexistente, un ID duplicado o una relación de imagen incorrecta también puede provocar fallos en Office.
Preview

Revisa la cinta sin abrir Excel, Word o PowerPoint.

La vista previa visual interpreta las pestañas, grupos y controles del XML y los muestra dentro de un entorno que imita el host Office correspondiente. La apariencia cambia según se trate de Excel, Word o PowerPoint, e incluye una representación de Backstage cuando el XML la contiene.

ExcelCinta y espacio de hoja.
WordCinta y página de documento.
PowerPointCinta y diapositiva.

La vista previa es una simulación para revisión visual. La validación definitiva de comportamiento sigue siendo abrir el archivo en Microsoft Office.

Iconos

Usa imageMso o administra recursos embebidos.

Ribbon UI Studio mantiene un catálogo de nombres imageMso y ofrece un navegador para localizar iconos. Cuando el Ribbon utiliza imágenes personalizadas, el editor administra los archivos dentro de customUI/images/ y sus relaciones.

imageMso

Usa nombres de iconos integrados de Office directamente en atributos como imageMso="HappyFace".

Imágenes personalizadas

Agrega, elimina o renombra imágenes embebidas y actualiza la relación correspondiente dentro del paquete.

Si agregas una imagen personalizada, usa el identificador que RibbonX espera y verifica después la vista previa y el diagnóstico de recursos.
VBA

Genera los callbacks que el XML realmente necesita.

La herramienta lee el RibbonX activo, identifica los atributos de callback y crea las rutinas que faltan en el módulo RibbonCallbacks. El resultado se abre en su propia pestaña VBA para continuar editándolo sin sobrescribir el XML.

Ejemplo — onAction
Option Explicit

Public Sub MyAction(control As IRibbonControl)
    MsgBox "Hello from Ribbon UI Studio", vbInformation
End Sub
Formatos sin macros: si el archivo actual termina en .xlsx, .docx o .pptx, guarda primero como .xlsm, .docm o .pptm antes de generar callbacks.
Proyecto VBA

Edita varios módulos VBA desde el mismo proyecto.

Cuando un archivo contiene proyecto VBA, Ribbon UI Studio puede enumerar sus módulos y abrirlos individualmente. El backend incluye operaciones para guardar uno o varios módulos, renombrarlos, eliminarlos e importar formularios.

Edición por pestañas

Cada módulo VBA conserva su nombre y contexto en Monaco, lo que permite trabajar con varios módulos sin mezclar su contenido.

Guardado conjunto

Cuando hay varios cambios pendientes, pueden escribirse en una sola automatización de Office para reducir aperturas repetidas del host.

VBA es código ejecutable. Revisa siempre el contenido antes de guardar un archivo recibido de terceros y prueba tus cambios en una copia.
Office Add-ins

Crea un complemento base para Excel, Word o PowerPoint.

Ribbon UI Studio puede crear el archivo nativo del complemento, agregar un módulo RibbonCallbacks, registrar la parte RibbonX y abrir automáticamente el resultado para seguir trabajando.

Excel

Genera .xlam con RibbonX y VBA.

Word

Genera .dotm con RibbonX y VBA.

PowerPoint

Genera .ppam con RibbonX y VBA.

Puedes elegir el esquema RibbonX de Office 2007 o el esquema de Office 2010+ al crear el complemento. La plantilla inicial incluye una pestaña, un grupo, una acción principal y un botón de información como base de desarrollo.

El complemento nuevo se abre automáticamente en el editor, de modo que puedes continuar con XML, callbacks, iconos y vista previa sin iniciar otro flujo.
Distribución

Convierte el add-in terminado en un instalador de Windows.

Para formatos de complemento empaquetables, Ribbon UI Studio dispone de una configuración de instalador con nombre de producto, versión, compañía, icono y opciones relacionadas con el paquete. Antes de iniciar el empaquetado guarda los cambios pendientes del XML o VBA.

DatoUso
Product nameNombre visible del complemento en el instalador.
VersionVersión de la distribución.
CompanyEditor o desarrollador.
IconIcono del instalador.
Obfuscate VBAOpción de procesamiento del código VBA cuando corresponda.
Backend actual: la ruta de construcción activa continúa utilizando Inno Setup 6. Si iscc.exe no está instalado en Program Files, Ribbon UI Studio no inicia la generación del instalador.
Automatización

Crea complementos desde la línea de comandos.

El ejecutable reconoce comandos de creación para los tres hosts Office. El segundo argumento es la carpeta destino. También puedes pasar directamente la ruta de un archivo compatible para abrirlo al iniciar.

Comandos disponibles
"Ribbon UI Studio.exe" --create-excel-2010 "C:\Output"
"Ribbon UI Studio.exe" --create-excel-2007 "C:\Output"
"Ribbon UI Studio.exe" --create-word-2010 "C:\Output"
"Ribbon UI Studio.exe" --create-word-2007 "C:\Output"
"Ribbon UI Studio.exe" --create-ppt-2010 "C:\Output"
"Ribbon UI Studio.exe" --create-ppt-2007 "C:\Output"

"Ribbon UI Studio.exe" "C:\Projects\MyAddin.xlam"

Estos comandos automatizan la creación o apertura. La edición posterior continúa usando el mismo archivo Office y las mismas reglas de guardado que la interfaz gráfica.

Solución de problemas

Los fallos más comunes y dónde mirar primero.

ProblemaQué comprobar
Office no muestra la cintaValida el XML, confirma el namespace, revisa IDs y verifica que la parte customUI esté registrada.
El botón aparece pero no respondeComprueba el nombre de onAction y que exista una rutina VBA con la firma correcta.
No se pueden generar callbacksEl documento puede ser un formato sin macros. Guarda como .xlsm, .docm o .pptm, o trabaja en un add-in.
Una imagen personalizada no apareceRevisa el archivo dentro de customUI/images, la relación y el identificador usado por el XML.
No se genera el instaladorComprueba que Inno Setup 6 esté instalado y que iscc.exe sea accesible.
PowerPoint PPAM se comporta distintoLos PPAM requieren un tratamiento especial del proyecto VBA. Evita forzar el archivo como si fuera una presentación normal.
Cuando un cambio parezca correcto en el editor pero falle en Office, usa este orden: Validar XML → Diagnóstico → Preview → Guardar → cerrar Office → volver a abrir el archivo.
Flujo recomendado

Trabaja rápido sin perder trazabilidad.

  • Mantén una copia del archivo antes de modificar RibbonX o VBA.
  • Usa IDs únicos y nombres de callbacks descriptivos.
  • Valida el XML antes de generar callbacks.
  • Prueba primero la vista previa y luego el archivo real en Office.
  • Guarda los cambios del editor antes de crear un instalador.
  • Para proyectos grandes, separa las responsabilidades VBA en módulos en lugar de concentrar todo en RibbonCallbacks.
  • Cuando distribuyas un add-in, prueba instalación, carga en Office y desinstalación en una máquina distinta a la de desarrollo.
